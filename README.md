# AI 數據分析工作坊 | AI-Assisted Data Analysis

用 AI 協助完成一次**真正站得住腳**的數據分析 —
從一句模糊的商業抱怨，到一份數字經過驗證的報告，再到一個持續運轉的儀表板。

---

## 📖 這個課程在教什麼

市面上不缺「怎麼跟 AI 聊天」的教學，也不缺「怎麼寫 Pandas」的教學。
本課程要補的是中間那一段：**當 AI 願意幫你做分析時，你怎麼確保它沒有在唬你。**

三個核心能力：

| 能力 | 為什麼重要 |
| :--- | :--- |
| **把商業問題轉成數據問題** | 「感覺最近業績變差」不是一個能分析的問題。這一步做不好，後面全白做。 |
| **用 AI 執行分析並自我驗證** | AI 寫得出 RFM 程式碼，但它也寫得出一個看起來很合理的假數字。差別在你有沒有要求它驗算。 |
| **把洞察變成決策與監控** | 一份沒人看的報告等於沒做。要能收斂成建議，並昇華成持續監控的儀表板。 |

## 🧭 六階段分析工作流

**前一階段的產出，就是後一階段的輸入。** 完整說明見 [`上課用prompt/分析師武器庫.md`](上課用prompt/分析師武器庫.md)。

| 階段 | 資料夾 | 做什麼 | 產出 |
| :--- | :--- | :--- | :--- |
| **00** | `00問題定義研究/` | 把模糊需求轉成可量化的分析問題 | 分析問題定義書 |
| **01** | `01資料描述/` | 產出數據卡，看清楚資料的真面目 | 數據卡 |
| **02** | `02數據分析/` | 選擇分析框架，並**實際執行分析** | 已驗證的關鍵洞察 + 可重跑腳本 |
| **03** | `03圖表選用/` | 挑對圖表，讓洞察一眼看懂 | 圖表設計建議 |
| **04** | `04報告呈現/` | 產出金字塔原則報告，**逐項驗算每個數字** | 分析報告 + 儀表板藍圖 |
| **05** | `05儀表板上線_streamlit/` | 生成並部署 Streamlit 應用 | 上線的儀表板 |

> 💡 階段編號一律對齊資料夾前綴，不會有「第三階段到底是哪個資料夾」的困惑。

## 🛠️ 兩種使用模式

同一套模板，兩種用法。差別在**誰去碰資料**：

| | **模式 A：聊天視窗** | **模式 B：AI Coding** |
| :--- | :--- | :--- |
| 環境 | ChatGPT / Claude 網頁版 | Claude Code / Antigravity / Cursor |
| 你要做的事 | 自己跑 Pandas，把結果貼進 Prompt | 給路徑，說需求 |
| AI 做的事 | 依你貼的內容整理與撰寫 | **自己讀檔、自己算、自己驗證** |
| 適合誰 | 沒有開發環境的學員 | 想讓 AI 真的幫你跑數字的人 |

**模式 B 的關鍵**：專案根目錄的 `AGENTS.md` 已經寫好資料集契約與分析鐵律，
agent 一進來就知道欄位語意、已知地雷，以及「每個數字都必須實際算出來」這條規矩。

**本專案不綁定任何一款 coding agent。** Antigravity、Codex、opencode 都原生讀 `AGENTS.md`；
Claude Code 讀的是 `CLAUDE.md`，而本 repo 的 `CLAUDE.md` 只是一層 `@AGENTS.md` 的薄封裝 ——
四款讀到的是同一份契約，避免兩份文件走樣。

> 🛠️ **還沒裝好環境？** 從 [`docs/README.md`](docs/README.md) 開始 ——
> 那裡有四款 agent 的對照表、選擇建議，以及一個「怎麼確認它真的讀到專案契約」的驗收提問。
> 每一款都有各自的安裝 SOP（前置檢查、認證流程、常見卡關症狀處置）與指令手冊。

> ⚠️ 模式 A 有個硬限制：**聊天視窗算不了 52 萬筆資料**。
> 階段 02 的「執行分析」與階段 04 的「數字驗算」只在模式 B 下才成立。
> 在聊天視窗做這兩步時，數字必須由你自己算好帶進去 —
> **不要叫聊天視窗「估一個大概」，它會給你一個很像真的假數字。**

## 💡 三條心法

> **「AI 最危險的不是算錯，是算得很有說服力。」**

1. **先看資料，再談結論。** 不要憑欄位名猜語意 — 這個 repo 的資料集裡就有
   「總額不等於單價乘數量」的欄位。
2. **每個數字都要有出處。** 說不出是哪支腳本哪一段算的，那個數字就不該進報告。
3. **清洗要留紀錄。** 樣本從 52 萬掉到 40 萬卻沒人提，是分析報告最常見的隱形謊言。

## 🔬 一支合格的分析腳本長什麼樣

不是「跑出圖」就算完成。它的終端機輸出應該像這樣 —— **這才是重點**：

```
[合併] <原始列數> → 去重後 <列數>（移除重疊期間的 <n> 筆重複交易）

[清洗紀錄]
步驟                              剔除     佔原始       剩餘  理由
原始資料                             -        -    <列數>  -
剔除退貨單 (InvoiceNo 以 C 開頭)     <n>    <x.x%>    <列數>  退貨非有效消費，會扭曲 Frequency
剔除 CustomerID 缺失                <n>    <x.x%>    <列數>  無客戶編號無法歸戶到個人
...

[樣本影響] 清洗後保留原始資料的 <x.x%>

[自我驗證]
  分群完整性：RFM <n> 位 = 清洗後 <n> 位 ✅
  營收加總：RFM 合計 <金額> = 明細合計 ✅
  交叉驗算：<某個關鍵數字>（兩種算法一致）✅
```

**每一刀都攤開來講，每個數字都驗算過。** 這就是這門課要你養成的習慣。
各項規範的逐條對照見 [`AGENTS.md`](AGENTS.md) 第 7 節。

> 📁 完整的可執行範例放在 [`solutions/`](solutions/)，它是**案例一的參考解答**。
> 建議先自己走完階段 02+ 再打開 —— 直接看會覺得每一步都很合理，
> 但那是看懂，不是做得出來。
