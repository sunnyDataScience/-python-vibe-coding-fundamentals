# Prompt 模板：AI 生成數據卡 (Data Card)

**🎯 目標**：快速、全面地理解一個全新的數據集，生成一份標準化的「數據卡」，
作為後續分析的基礎文檔與團隊溝通的依據。

> 本檔已合併舊版的 `dataset_documentation_prompt.md`。
> 兩者原本內容幾乎相同，差別只在多了「維護者」與「主要用途」兩欄 —
> 現已整併為下方的**選配欄位**，需要對外共享的技術文檔時一併填寫即可。

---

## 使用前先選模式

| | **模式 A：聊天視窗** | **模式 B：AI Coding** |
| :--- | :--- | :--- |
| 環境 | ChatGPT / Claude 網頁版 | Claude Code / Antigravity / Cursor |
| 你要做的事 | 自己先跑 `df.info()`、`df.describe()`，把輸出貼進 `CONTEXT` | 只給資料集路徑 |
| AI 做的事 | 依你貼的摘要整理成數據卡 | **自己讀檔、自己算**，數字直接來自原始資料 |
| 數字可信度 | 取決於你貼的內容是否完整 | 可重現、可驗算 |

> ⚠️ **模式 A 的鐵則**：`CONTEXT` 沒貼到的統計量，AI **不會知道**。
> 若它填出了你沒提供的數字（例如某欄的缺失率），那是編的 — 請要求它標註「未提供」而非猜測。
> 模式 B 請直接用下方的〈模式 B 專用指令〉，不要用模式 A 的模板。

---

## 模式 A：聊天視窗用（複製以下全文）

```markdown
# 🧑‍💻 角色
你是一位資深的數據管理專家 (Data Steward)，你的核心職責是為團隊的數據資產創建清晰、準確且易於理解的文檔。你擅長從原始數據中提取元數據 (Metadata) 和關鍵統計信息，並將其組織成一份結構化的數據卡。

# 📝 任務
1.  分析我提供的數據集摘要（`head()` / `df.info()` / `df.describe()` 的輸出）。
2.  生成一份完整的「數據卡」，內容需包含：
    *   **數據集總覽 (Dataset Overview)**：數據來源、最後更新時間、總行數、總列數。
        （選配：數據集維護者、主要用途 — 需要產出對外共享的技術文檔時填寫）
    *   **數據列詳解 (Column Details)**：為每一列提供名稱、數據類型、缺失值比例、唯一值數量、簡要描述和數據範例。
    *   **初步數據品質評估 (Initial Quality Assessment)**：識別潛在的數據品質問題，如異常值、不一致的格式、高比例的缺失值等。
    *   **探索性分析建議 (Next Steps for EDA)**：基於數據卡的內容，提出 2-3 個接下來可以深入探索的分析方向。

# ⚠️ 準確性要求
- **只使用我提供的資訊。** 我沒有提供的統計量（缺失率、唯一值數、最大最小值等），請在對應欄位填 `未提供`，**不要推測或編造數值**。
- 若你認為某個關鍵統計量缺失、影響判斷，請在數據卡最後列出「建議補充的資訊」清單。

# CONTEXT (背景資訊)
- **數據集來源**: [例如：`資料集/SuperMarket_Sales_2025/Taiwan_SuperMarket_Sales_2025_Practice.csv`]
- **數據集預覽**: 
  ```
  [請在此貼上 `df.head()`、`df.info()` 和 `df.describe()` 的輸出結果]
  ```

# 💡 輸出格式
請嚴格按照以下 Markdown 格式生成「數據卡」：

---
### **數據卡：[數據集名稱]**

**1. 數據集總覽**
- **數據來源**: `資料集/SuperMarket_Sales_2025/Taiwan_SuperMarket_Sales_2025_Practice.csv`
- **數據維度**: 1,030 行 x 28 列
- **時間範圍**: 2025-01-01 ~ 2025-03-30
- **數據集維護者**: [選配，例如：課程助教團隊]
- **主要用途**: [選配，例如：學員練習用的台灣超市銷售數據，含刻意注入的缺失值與異常值]

**2. 數據列詳解**

| Column Name | Data Type | Missing % | Unique Values | Description | Example |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `Invoice ID` | object | 0.00% | 1000 | 發票號碼（**注意：1030 列僅 1000 個唯一值，存在重複**） | `149-71-6266` |
| `Date` | object | 0.00% | 85 | 銷售日期，格式 `YYYY-MM-DD` | `2025-01-28` |
| `Branch` | object | 0.00% | 7 | 通路品牌 | `楓康` |
| `City` | object | 0.00% | 6 | 六都 | `台北市` |
| `Product line` | object | 0.00% | 6 | 商品類別 | `運動休閒` |
| `Unit price` | float64 | 0.97% | 982 | 商品單價 | `2248.42` |
| `Quantity` | float64 | 2.04% | 29 | 銷售數量（**存在負值，最小 -9**） | `9.0` |
| `Sales` | float64 | 0.00% | 998 | 銷售總額 | `21247.53` |
| `Rating` | float64 | 3.88% | 86 | 顧客評分 | `4.5` |
| ... | ... | ... | ... | ... | ... |

**3. 初步數據品質評估**
- **缺失值**: `Rating` (3.88%)、`Membership_Level` (4.95%)、`Quantity` (2.04%) 等多欄有缺失，需個別決定填充或剔除策略。
- **異常值**: `Quantity` 出現負值（最小 -9），需確認是退貨記錄還是輸入錯誤。
- **主鍵重複**: `Invoice ID` 唯一值少於總行數，不可直接當主鍵使用。
- **恆定欄位**: `gross margin percentage` 全表僅一個值，對分析無區辨力。
- **對帳不一致**: 有 20 列的 `Sales` 不等於 `cogs + Tax 5%`，金額欄位間存在矛盾。

**4. 探索性分析建議**
1.  **通路表現比較**: 比較 7 個 `Branch` 在客單價、毛利與 `Rating` 上的差異。
2.  **時段與促銷效果**: 分析 `Shopping_Period`、`Is_Promotion` 對 `Sales` 的影響。
3.  **會員價值分層**: 探索 `Membership_Level` 與 `Age_Group` 在消費金額上的交叉關係。
---
```

## 模式 B：AI Coding 專用指令（貼給 agent）

```markdown
請為以下資料集產出一份「數據卡」，寫入 `reports/data_card_<資料集名稱>.md`。

# 資料集
[例如：資料集/SuperMarket_Sales_2025/Taiwan_SuperMarket_Sales_2025_Practice.csv]

# 執行要求（不要用估的，全部實際跑出來）
1. 讀取資料集。編碼與已知地雷請先查專案根目錄的 `AGENTS.md`。
2. 實際計算並填入下列每一項，**數據卡裡不得出現任何未經計算的數字**：
   - 總行數、總列數、時間範圍（若有日期欄）
   - 每欄的 dtype、缺失率、唯一值數、一筆真實範例值
   - 數值欄的 min / max / mean / median / 分位數
   - 類別欄的類別數與前幾大類別佔比
3. 主動檢查以下品質問題，有就寫進「初步數據品質評估」，沒有就明講「已檢查，無此問題」：
   - 主鍵是否真的唯一（唯一值數 vs 總行數）
   - 是否有恆定欄位（唯一值 = 1，對分析無區辨力）
   - 數值欄是否有不合理的負值或 0
   - 衍生欄位間是否自洽（例如 總額 是否等於 單價 × 數量、或 成本 + 稅）
   - 日期欄是否有跨不合理範圍的值
4. 把你用來計算的程式碼一併保存到 `scripts/profile_<資料集名稱>.py`，讓這份數據卡可以被重跑驗證。
5. 最後列出 2-3 個「探索性分析建議」，每一個都要說明**為什麼這份資料撐得起這個分析**。

# 輸出格式
沿用本檔〈模式 A〉的「數據卡」Markdown 結構（總覽 / 列詳解 / 品質評估 / EDA 建議）。
```
