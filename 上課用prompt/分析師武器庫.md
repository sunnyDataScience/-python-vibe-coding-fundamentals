# 數據分析師的 Prompt 武器庫（總索引）

這套武器庫把「一個模糊的商業問題」拆成六個階段，每個階段有一份可直接取用的 Prompt 模板。
**前一階段的產出，就是後一階段的輸入。**

> **本檔是索引，不放 Prompt 本文。**
> 每份 Prompt 只存在於它自己的檔案裡（單一真相源）。要用哪個階段，點連結進去複製該檔的內容。
> 舊版本曾把五個階段的全文複製到本檔，導致改了一邊另一邊沒同步 — 已移除。

## 兩種使用模式

這套模板可以在兩種環境下使用，**輸入方式不同**：

**模式 A — 聊天視窗**（ChatGPT / Claude 網頁版）
複製 Prompt 全文 → 手動填 `CONTEXT` → 貼上 `df.info()` 之類的資料摘要 → 取得文字產出。
適合沒有開發環境的學員。

**模式 B — AI Coding**（Antigravity / Claude Code / Codex / opencode）
直接叫 agent 讀 `階段檔案` 並指定資料集路徑，agent 會**自己讀檔、自己算、自己驗證**，不需要你貼任何統計摘要。
專案根目錄的 `AGENTS.md` 已經寫好資料集契約，agent 讀得到欄位語意與已知地雷。

> 🛠️ 環境還沒裝好？**四款 agent 都可以，選一個就好** ——
> 對照表、選擇建議與各自的安裝 SOP 見 [`docs/README.md`](../docs/README.md)。
> 那裡也有一個「怎麼確認它真的讀到專案契約」的驗收提問，裝完先跑一次。

> 模式 B 才有「階段 02+ 執行分析」和「報告數字驗算」這兩關 — 這是模式 A 做不到的（聊天視窗算不了 52 萬筆資料）。

**模式 B 的產出會落在專案根目錄這三個資料夾**（`AGENTS.md` 第 5 節的慣例）：

| 資料夾 | 放什麼 |
| :--- | :--- |
| `reports/` | 數據卡、洞察摘要、分析報告、驗算紀錄 |
| `scripts/` | 可重跑的分析腳本 |
| `charts/` | 圖表產出 |

`資料集/` 一律**唯讀**，清洗後的資料另存，不要覆蓋原始檔。

> 📁 **參考解答**放在 [`solutions/`](../solutions/)，對應案例一「尋找沈睡的鯨魚」。
> 它把階段 02+ 要求的每件事都做了一遍 — 清洗紀錄表、樣本影響評估、自我驗證、圖表落地。
> **建議先自己做完再打開** —— 直接看會覺得每一步都很合理，但那是看懂，不是做得出來。

## 使用建議

1. **不要跳階段。** 每個階段的 `CONTEXT` 都預期收到前一階段的完整產出，跳過會讓後面的模板缺乏依據而開始編造。
2. **問題太大就先拆。** 階段 00 產不出單一「核心問題」時，先用 `McKinsey分析架構流程.md` 拆議題樹。
3. **數字一律要驗。** 階段 04 產出的報告骨架裡所有百分比都是**佔位符**，交付前務必跑 `報告數字驗算.md`。
4. 完整的走查範例與流程圖見 [分析師武器庫_使用手冊.md](分析師武器庫_使用手冊.md)。
